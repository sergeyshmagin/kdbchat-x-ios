# Решение проблемы с входящими звонками через LiveKit

## Проблема

Текущая архитектура имела фундаментальную проблему:
- LiveKit аутентификация происходила только при начале звонка
- Пользователь B, который еще не звонил, не мог получать входящие звонки
- VoIP push токены не регистрировались до первого звонка

## Решение

### 1. Активация VoIP Push Registry при старте приложения

В файле `LiveKitCallKitService.swift` добавлена регистрация VoIP пушей сразу при инициализации:

```swift
pushRegistry.delegate = self
pushRegistry.desiredPushTypes = [.voIP] // Добавлено
```

Это гарантирует, что iOS запросит VoIP токен сразу при запуске приложения.

### 2. Регистрация VoIP токена в Matrix при входе

Процесс теперь работает так:
1. При входе пользователя вызывается `configureWithClientProxy`
2. iOS генерирует VoIP push токен
3. Токен автоматически регистрируется в Matrix через `registerVoIPPushToken`
4. Пользователь готов принимать звонки

### 3. Архитектура входящих звонков

Теперь входящие звонки работают через два механизма:

**Приложение в фоне/закрыто:**
1. Matrix отправляет VoIP push
2. iOS пробуждает приложение
3. CallKit показывает входящий звонок
4. LiveKit аутентификация происходит только при ответе

**Приложение активно:**
1. Matrix событие m.call.invite приходит через timeline
2. Приложение показывает CallKit UI
3. LiveKit подключение при ответе

## Преимущества решения

1. **Мгновенная готовность к звонкам** - сразу после входа
2. **Работа в фоне** - VoIP пуши пробуждают приложение
3. **Экономия ресурсов** - LiveKit соединение только при активном звонке
4. **Надежность** - не зависит от состояния LiveKit до момента ответа

## Дополнительные улучшения

Для полноценной работы системы звонков рекомендуется:

1. Реализовать отправку m.call.invite событий через Matrix
2. Добавить таймауты для неотвеченных звонков
3. Улучшить обработку состояний звонка (ringing, declined, busy)
4. Добавить поддержку повторных звонков
